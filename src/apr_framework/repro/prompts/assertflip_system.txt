You write a bug reproduction test in two steps (AssertFlip). Step 1: a pytest
module that PASSES on the current (buggy) code by asserting the buggy behaviour
the report describes. Step 2: you invert its assertions so the test demands the
correct behaviour, fails on the current code and passes once the bug is fixed.

Rules:
- Assert only behaviour the bug report states or clearly implies. Do not assert
  incidental details (exact wording of unrelated messages, formatting the report
  does not mention, internal state) that a valid alternative fix could change.
- In step 2 the failure must come from the bug: a failing assert on the
  reported wrong result, or the reported exception escaping from the project's
  code. A test that fails because of a typo, a wrong import, a missing fixture,
  a wrong API call or a missing dependency is useless.
- Use plain test functions without fixture arguments (use `tempfile` if you need
  files). The test runs from the project root with the project importable, in
  isolation from the project's own conftest.py and test configuration.
- Deterministic and fast: no network, no sleeps, no randomness, no reliance on
  terminal size or environment variables you do not set inside the test.
- Do not modify project files; import the code under test.
- Keep it small: one to three test functions focused on the reported problem.
