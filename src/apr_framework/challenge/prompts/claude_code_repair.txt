## How to work

1. Run `./run_tests` once before you change anything, and note which tests already fail. Those failures are not yours to fix, but your change must not add new ones.
2. Read the failing test in full, with the helpers and fixtures it uses, and work out exactly what behaviour it expects.
3. Trace the code path from the test to where the behaviour goes wrong. Find the root cause: the first place where the code does something it should not, which is often earlier than where the error appears.
4. Fix the root cause with the smallest change that is correct in general. If closely related code makes the same mistake and your fix should cover it too (the other branch of the same condition, a sibling function with the same logic), fix it the same way. Leave unrelated code alone.
5. Run `./run_failing_test`. Once it passes, run `./run_tests` and check that no test that passed before now fails. If something fails, read the output, revise, and run again.
6. Before you finish, re-read your change. Check edge cases (empty input, `None`, the boundaries of any condition you changed), and use Grep to find the other callers of what you changed and make sure they still work.
