# FL-Guided Repair and Perfect Fault Localization Baseline (Assignment 4 — Task 4)

Task 4 asks us to evaluate the **LLM-based repair backend** under the two fault
localization conditions and to make both accessible via the CLI, recording which
FL mode was used in every result file:

1. **Automated FL**  the suspicious location(s) come from the Assignment-2
   fault localizer (here: SBFL / Ochiai, statement granularity), then the top-N
   ranked lines are fed into the LLM prompt.
2. **Perfect FL** the ground-truth fault location is taken directly from the
   BugsInPy developer fix (`bug_patch.txt`), bypassing the FL step entirely.

Both runs use the identical repair backend and configuration; **only the
fault-location source differs**, so the two rows isolate the effect of FL
quality on the LLM repair outcome.

## Configuration

| Setting | Value |
|---|---|
| Technique | `llm` |
| Model | `gpt-4o-2024-05-13` |
| Temperature | 0.8 |
| Max candidates / location | 5 |
| Top-N locations | 5 |
| Budget | 200 |
| Auto-FL family / metric | SBFL / Ochiai (statement) |
| Perfect-FL source | BugsInPy developer fix (`bug_patch.txt`) |

Reproduce (inside the Docker container, with `GPT_AT_RUB_API_KEY` exported):

```bash
# Perfect FL baseline
python -m apr_framework repair --project black --bug 1 --technique llm --fl-mode perfect

# Automated FL (SBFL / Ochiai)
python -m apr_framework repair --project black --bug 1 --technique llm --fl-mode auto --fl-family sbfl
```

## Results - black #1

| Run | FL mode | Status | Generated | Plausible | Correct | Time |
|---|---|---|---|---|---|---|
| run_167 | perfect | plausible | 14 | 2 | 0 | 80.9s (1st plausible 52.4s) |
| run_168 | auto (SBFL/Ochiai) | failed | 25 | 0 | 0 | 49.9s |

Perfect FL found **2 plausible** patches but **0 correct**  the LLM produced
patches that pass the trigger test + regression check without matching the
developer fix (i.e. they are overfit to the failing test). Automated FL
generated more candidates (25 vs. 14, because SBFL surfaces several suspicious
lines to prompt against) but produced **no plausible patch at all** on this bug:
the developer-fix line was not localized precisely enough for the LLM to fix it
from the surrounding context.
